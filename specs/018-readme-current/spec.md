# Feature Specification: A README that describes the bar that ships

**Feature ID**: `018-readme-current`

**Status**: Draft

**Date**: 2026-09-07

**Input**: The README must be brought up to date, pushed to main, reflected in
the locally installed statusline, and then checked against a real session in
the barbershop project to confirm it behaves as described.

## Problem

The README describes a bar that no longer exists. Six days of changes landed
without it, and the gap is not cosmetic: someone installing from this
repository would be told the wrong number of lines, the wrong settings key,
and icons the bar stopped drawing.

What it currently claims, and what is true:

| README says | The bar does |
|---|---|
| "A four-line status bar" (line 3) | Three lines since the merge of lines 3 and 4 |
| Registers `taskCommand` for subagent rows (line 50) | Registers `subagentStatusLine`; `taskCommand` was never a key Claude Code read |
| Both resets share one dimmed segment, `🕞 1h29m / 3d` (line 222) | Each window carries its own reset; the merged segment and its clock faces are gone |
| Shedding: skills, then the model line, then the directory line, line 4 last (line 152) | Line 2, then any arranged line 4, then line 1, with line 3 last |
| `nf-md-circle` / `nf-md-circle_outline` for working and idle (line 654) | A hammer and a coffee cup |
| Clock faces are the one place emoji stay (line 670) | No emoji on the bar at all |
| Nothing about `NO_COLOR` | `NO_COLOR` turns colour off, and the powerline separator with it |
| Nothing about what a subagent row carries | Rows show the work, the skills recorded against that agent, the tier, a context gauge, tokens and age, in aligned columns |
| Nothing about roster isolation | The roster is keyed per session, so two windows no longer read each other's agents |

## Requirements

- **FR-001**: Every count, key name, icon and behaviour the README states matches
  what the shipped code does.
- **FR-002**: The generated preview images match the current renderer, since
  Principle VIII forbids hand-drawn output in documentation.
- **FR-003**: What a subagent row shows is documented, including that the skills
  column depends on an attribution Claude Code does not guarantee.
- **FR-004**: `NO_COLOR` is documented alongside the other environment switches.
- **FR-005**: The change reaches `main` and the locally installed plugin.
- **FR-006**: The result is checked against a live barbershop session rather
  than only against a fixture.

## Success Criteria

- No statement in the README contradicts the code or the constitution.
- A reader following the install section gets a working bar with subagent rows
  drawn by this plugin.
- The barbershop window renders three lines whose content matches what the
  README leads a reader to expect.

## Assumptions

- The README stays a single file rather than being split; its length is not the
  complaint.
- Screenshots and preview SVGs are regenerated by the existing scripts rather
  than edited.

## Out of Scope

- The two open findings recorded in `specs/017-line-legibility`: the mixed-width
  `█▓▒░` gauge and the ambiguous-width `·` separator under a CJK-configured
  terminal. Documenting them is not fixing them, and the fix is a visual
  redesign the owner has not asked for.

# Implementation Plan: Copilot parity

**Branch**: `feat/copilot-parity` | **Date**: 2026-10-06 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/033-copilot-parity/spec.md`

## Summary

Nine changes, each small, that make the bar under GitHub Copilot CLI read like the bar under
Claude Code: the real terminal size from `/dev/tty`, three payload or log fallbacks (context,
effort, resolved model), todos from the session's SQLite file, repeat skill invocations, an AI
credits chip, the monthly quotas through the detached refresh, and an installer that refreshes
every 10 seconds and can quiet Copilot's own footer.

## Technical Context

**Language/Version**: JavaScript ES modules, Node 18+

**Primary Dependencies**: none at runtime. `node:sqlite` when the running Node has it (22.13+, 23.4+; earlier versions need --experimental-sqlite),
else the `sqlite3` CLI outside Windows; `gh` for the quota, only in the detached refresh.

**Storage**: the Copilot events sidecar (schema 2), one global cache entry `copilotQuota`, and
`~/.claude/statusline/copilot-footer.json` for the footer record.

**Testing**: `npm test`, with fixtures from real Copilot 1.0.91 payloads and events.

**Target Platform**: Linux, macOS, Windows (no `/dev/tty` and no `sqlite3` CLI on Windows).

**Project Type**: CLI (status line renderer)

**Performance Goals**: under Copilot one `open` of `/dev/tty`, one small settings read and, when
a `session.db` exists, one read-only query per redraw. No network on the redraw path.

**Constraints**: the redraw's 300 ms budget; Claude Code's output unchanged.

## Design decisions

1. Width (item 1). `layout.js` gains `copilotTerminal()`: only when `COLUMNS` is unset, the
   harness is Copilot and the platform is not Windows, it opens `/dev/tty`, reads `columns` and
   `rows` from a `tty.WriteStream`, closes it, and subtracts `statusLine.padding`. Any error
   gives the old answer (120, unlimited). `renderPayload` asks for it only when the caller did
   not pass a size. `doctor` says which source the width came from.
2. Context (item 2). `getContextPercent` and `getContextTokens` fall back to the Copilot
   fields only when `used_percentage` / `context_window_size` are null. Claude never sends the
   fallback fields, so its output is unchanged.
3. Effort and model (items 3, 4). The events reader folds three more root facts: the newest
   non-null effort (user message or model change), the newest resolved model (root assistant
   message, or the auto router's choice), and the session limit. The sidecar schema goes to 2,
   so an old sidecar is a miss and the log is re-read once. The settings fallback reads
   `effortLevel` from `$COPILOT_HOME/settings.json`, through the comment-tolerant reader that
   install already had, now shared in `src/copilotSettings.js`.
4. Todos (item 5). `src/copilotTodos.js` checks that `session.db` exists, then tries
   `node:sqlite` (`createRequire`, with Node's experimental warning swallowed for that one
   require), then `sqlite3 -readonly -json` with a 100 ms timeout outside Windows. Rows map to
   `{ done, total, current }`, the shape Claude's reader returns.
5. Repeat skills (item 6). A fall-through case.
6. AI credits (item 7). New segment `aiCredits` (line 3, order 56, priority 61, ramp). It
   draws `<formatted> AIC`, or `<used>/<max> AIC · N%` when a limit is in force, with the ramp
   colour of N. Only when credits were used, like the premium requests chip.
7. Monthly quota (item 8). New probe `copilotQuota` in `refresh.js`, cached under one global
   key like rtk (the quota is the account's, not the repository's), max age 10 minutes so the
   refresh runs every 5. The reader runs only under Copilot. Two new segments, `premiumQuota`
   (order 41, priority 71) and `chatQuota` (order 51, priority 69), sit where the 5-hour and 7-day chips sit under Claude
   Code, which are absent under Copilot. Each reads `month <name> N% · <reset date>`, with the
   band mark and `full` like the windows, and the date as its shed variant.
8. Install (item 9). `COPILOT_REFRESH_INTERVAL_SECONDS = 10`. Copilot redraws only on its
   own state changes, and the things it does not redraw for are exactly what this feature adds:
   a resize, a todo, an effort change by `/model`, a quota refresh. Ten seconds keeps that lag
   under the time it takes to look down at the bar, at six renders a minute of about 50 ms each.
   Five would double that cost to shave five seconds, and the quota itself changes every five
   minutes. Claude Code keeps 60.

## Results

Recorded 2026-10-06, on macOS with Node 24.21.0.

- `npm test`: 737 passed, 0 failed (712 before the feature). The new cases are in
  `scripts/tests/copilot-parity.test.js`; three existing cases changed on purpose: the Copilot
  install's interval (60 to 10), the ramp channel list, and the composer's golden bar.
- Real payload, real session. The payload Copilot 1.0.91 sent to a capture command, pointed at
  real session `8dd93b79` and run through `bin/cli.js render` the way Copilot spawns it (piped
  stdio, no `COLUMNS`, a pty as controlling terminal). At 100 and 150 columns line 3 read
  `gpt-6-luna (auto)  medium  Context 0%  13m  0.64 AIC  rtk 68% saved`. Before this feature
  it read `Auto  Context ?%  13m`. At 60 columns every line fit; the duration, the credits
  and the savings were shed by priority.
- `/dev/tty` read: 97x33 in a pty, 2.6 ms including loading `node:tty`. With no controlling
  terminal it returns null and the width stays 120.
- `doctor` with the same payload in a 117-column pty: `terminal: 117 columns (read from
  /dev/tty: Copilot CLI sets no COLUMNS), 40 rows`, and for this machine's own Copilot install
  `refreshes every 60s; Copilot's footer repeats some of the bar`, since it predates this
  feature.
- Quota, live: `gh api /copilot_internal/user` for this account normalised to chat 3% of 200,
  premium absent (entitlement 0 on `free_limited_copilot`), reset 2026-11-01. So on this
  account the bar shows one chip, `month chat 3% · Nov 1`.
- `session.db`: none of this machine's ten sessions has one, because none used the sql tool.
  The reader was checked against a WAL-mode database with Copilot's documented `todos` columns,
  through both `node:sqlite` and the `sqlite3` CLI, and the file's bytes were unchanged after.
- `skill.invoked_ref` and `session.session_limits_changed` appear in Copilot's schema and
  bundle but in none of the local logs, so their cases are built from the schema's shapes.
- Previews: every existing scenario regenerated byte-identical (SC-004). One new scenario,
  `docs/previews/copilot.svg`. The composer page was regenerated with 33 segments.
- Deviation from the first design: the quota chips rank 71 and 69, not in the band just under
  the windows. The composer fixture, which carries both Claude's windows and Copilot's month,
  showed them pushing the savings figure off a 200-column line, and the owner ranked that
  figure to survive. Under Copilot nothing else on the line ranks between them.
- Deviation: `harnessProbes` now lets a Copilot payload with no `transcript_path` keep the
  session probe it was given. A real Copilot payload always names its session directory, so
  this changes nothing at runtime, and it lets the composer fixture draw the Copilot chips.
